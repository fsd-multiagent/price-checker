## Findings

### F1. The packaged backend does not start, so "end to end in the browser" is not met at runtime (spec-to-implementation)

Source: `AGENTS.md` Known pitfalls ("Main code has no adapter beans until Epic 2, so the packaged backend does not start yet (story 1.6 deferral)"); `ro.pricechecker.lookup.AdapterCatalog` one-to-one id check (AD-7). Spring tests pass only through the test-only `lookup/StubAdapters`. Also from the same section: without a `RetailerHttp` bean every enabled retailer is `UNAVAILABLE`.
Effect: the epic goal's "end to end in the browser" is only shown in tests and CI, not with the running jar.
Disposition: **defer** to Epic 2 (the first real adapter and the `fetch` client). Make `StubAdapters` opt-in (`@Import`) in the same story, as the pitfall says.

### F2. Spring text logs share stdout with `LookupLog` JSON lines (story 1.4 deferral)

Source: `AGENTS.md` Known pitfalls (ADR 0017 entry).
Disposition: **defer**. It needs a logging config change before anything parses stdout.

### F3. Two story first rounds charged $14.86 and recorded no tokens (usage)

Source: `.sdlc/usage-summary.md:34-35`: `story:1-1-backend-scaffold/build r1` 5 attempts, $8.13, 5 incomplete; `story:1-2-web-scaffold/build r1` 5 attempts, $6.73, 5 incomplete. Also `learn:1-1-backend-scaffold/learn r1` (line 37), 1 incomplete. All 13 incomplete build attempts and the one learn attempt are in the first stories of the run.
Reading: every step of those rounds ended by timeout, crash or interrupt (summary lines 8-9), so it is about 16% of the epic's cost with no output. The pattern (whole rounds, at the start of the run, then none until 1-5 r1 and 1-3 r6) fits an environment or limit problem at run start more than too low a `max_turns`. The run state is not in this worktree, so the cause is not confirmed.
Disposition: **fix now** (process): action item A1.

### F4. Story 1.3 (API contract) took six build rounds, 23% of the epic's cost (usage)

Source: `.sdlc/usage-summary.md:39,41,45-47,49`: rounds r1–r6, 22 attempts, $21.95 of $93.79. `pipeline.yaml:27` has `max_rounds: 3`, so the later rounds came from `integrate` sending the story back to `build` (`pipeline.yaml:308`, `on_fail: build`) or from a resume.
Reading: the contract story touches codegen in both the backend and web builds (C-3, ADR 0007); the AGENTS.md pitfalls show two cross-build traps (the `@emnapi` lockfile entries from story 1.3 and the generated code). Repeat rounds on build/CI mismatch are a dev-step problem, not a reviewer one.
Disposition: **fix now** (process): action item A2.

### F5. Code review is the second-largest cost (usage)

Source: `.sdlc/usage-summary.md:19`: Filofteia (Code Reviewer) 27 attempts, $29.56 (32%), against Marghioala (Developer) $45.75. Two reviewer steps run per round (`code_review` with `bmad-code-review`, which starts its own parallel reviewers, and `code_lens`; `pipeline.yaml:273-289`), plus Veronel (Security & Compliance) at $3.26.
Disposition: **fix now** (proposed config): action item A3.

### F6. Story 1.1's learn step took six rounds (usage)

Source: `.sdlc/usage-summary.md:37,42,48,50,54,56`: `learn:1-1-backend-scaffold/learn` r1–r6, $2.14. The other eight stories took one or two rounds.
Reading: cheap, but six rounds point at the gate rejecting the keeper's output again and again (the first learn branch, so docs drift was largest). Not a model or turns problem.
Disposition: **accept**, watch in Epic 2 (action item A4).

### F7. Wins the evidence confirms

- Security (Veronel) cost $3.26 over 13 attempts: the read-only reviewer with a narrow prompt is cheap.
