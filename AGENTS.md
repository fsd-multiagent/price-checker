## price-checker

A learning project for an automated multi-agent SDLC built on BMAD; the app (enter an EAN, compare prices across approved Romanian retailers, React + Java on one Azure VM) is the pretext. When a product question is ambiguous, choose the simplest option that keeps the demo working. The plan is `docs/automation-plan.md`; the spec is `docs/initial-spec.md`; BMAD outputs go to `_bmad-output/`.

## Policy

- Follow the rules in `docs/standards/` and cite their IDs (C-, T-, S-, I-, D-) in findings and commits.
- Never approve a retailer, run `terraform apply`/`destroy`, push or merge to `main`, or open SSH to the VM. The guard hook blocks these; escalate to the owner instead.
- Never contact a retailer domain unless `docs/source-register.md` marks it `Approved`. To propose one, set its Status to `Proposed`.
- Never edit `.claude/settings*.json`, `.claude/hooks/` or `docs/source-register.md` Status cells to get past a block; ask the owner.
- Never read `.env*`, `*.tfstate*`, `*.tfvars`, `~/.ssh` or `~/.azure`.
- Every architecture decision gets an ADR from `docs/adr/0000-template.md`, added to the index in `docs/adr/README.md` (D-2).

Change the contract first, then regenerate (C-3). OpenAPI Generator 7.27.0 generates Spring interfaces into `backend/build/generated/openapi` (package `ro.pricechecker.api.generated`, run by `compileJava`) and the web client into `web/src/generated/`. The backend build bundles them and `docs/source-register.md` into the jar under `registry/`; `ro.pricechecker.registry.Registry` loads them at start and refuses to start when `ConfigCheck` reports a violation. The rules are in the file headers.
- CI: `.github/workflows/ci.yml` runs jobs `orchestrator`, `backend`, `web` (`check` and `build`), `secret-scan` (gitleaks over the PR's or push's commit range) and `vulnerability-scan` (Trivy, runtime dependencies in lockfiles and the backend boot jar, HIGH and CRITICAL fail). The aggregate job `ci` is the one required check and fails when any job fails or is skipped (ADR 0024).
- Infrastructure: `infra/` (Terraform for the `prod` VM; commands and pitfalls in `infra/CLAUDE.md`, owner bootstrap and apply in `infra/README.md`); PR plan workflow `.github/workflows/terraform-plan.yml`

A plan usage limit pauses the run; while paused, `sdlc status` prints `plan usage limit: resume_at …` (also after an episode escalated the run).

  - `uv run sdlc usage [<run-id> | --all] [--by agent|stage|model|round|run] [--rebuild]` reports token use and cost from each run's `state.json` (read-only). The run itself appends to the ledger `<runs-dir>/usage.jsonl`; `--rebuild` regenerates it and refuses while a run is running (AD-24).

Before an epic retrospective the orchestrator writes `<worktree>/.sdlc/usage-summary.md`.
  - Path tiers in `sdlc/pipeline.yaml` (AD-26, ADR 0022), each entry a path prefix or an exact file:
    - `owner_only_paths` (`.claude/`, `.github/CODEOWNERS`, `docs/source-register.md`): reverted before every orchestrator commit and never proposed. A reviewer that changes one fails.
    - `protected_paths` (`sdlc/`, `orchestrator/`, `_bmad/custom/`, `docs/standards/`, and the `sdlc-commands` block below): an agent's edit is captured as a proposal, then reverted on its branch.
    - `review_paths` (`.github/workflows/`): never pushed from a proposal. On a learn branch an edit there becomes an issue.
    - A proposal becomes a PR on `proposal/<sha8>` cut from `origin/main`, labelled `owner-review`. When it touches `review_paths` or does not apply cleanly, it becomes an `owner-review` issue with the patch. Zamolxe (Orchestrator) never merges or auto-merges an `owner-review` PR; only the owner does. `sdlc status` lists them as `owner review: PR #n`; the saved search is `is:open label:owner-review`.
  - Issue runs (AD-27): `uv run sdlc story <issue>` and `uv run sdlc fix <issue>` (add `--dry-run` for fakes; issue 12 in `orchestrator/tests/fixtures/dryrun/issues/` is a factory story). The issue must be open, and its author, its last editor, whoever renamed it and whoever applied a `factory` label must be in `settings.owners`, or the command comments why and exits 1. A second run for an issue whose earlier run has not passed or escalated is refused. The issue holds one fenced `yaml` story block (`depends_on`, `touches`, `sources`, optional `acceptance`; `key` is derived as `0-<issue>-<slug>`; `touches`, `sources` and `depends_on` must be plain paths, domains and keys); a bad block escalates the run at once. Issue text reaches prompts only in the fenced "Untrusted issue text" section, and `sdlc resume` escalates the story if the issue changed.
  - A factory story keeps its edits to `protected_paths` and `review_paths` (owner-only paths and bookkeeping are still reverted; in `AGENTS.md` only the `sdlc-commands` block change is kept), and its tests gate runs only the branch point's block (the new block never runs before the owner merges it). A PR touching `protected_paths` in a factory story, `review_paths` in any run, or (any story) the `sdlc-commands` block, is created labelled `owner-review` and waits: the run goes on with independent work and ends `awaiting_owner` (exit 2). After preflight, the next `run`, `resume`, `story` or `fix` checks the PRs of `awaiting_owner` runs: merged (with the head that was opened for review) queues `sdlc resume <run>` ahead of the new work, once; a failed automatic resume is shown by `sdlc status` and not queued again. Closed, or merged with another head, escalates the story. On a dry-run, simulate the owner with `{"pr_states": {"<pr>": "MERGED"}}` in `<runs-dir>/fake-gh.json`.
  - One run at a time: a real `run`, `resume`, `story` or `fix` holds `fcntl.flock` on `_bmad-output/sdlc/lock`, whatever `--runs-dir` says (a dry-run locks beside its own runs dir). A second one is appended to `_bmad-output/sdlc/queue.jsonl` (never with `--repo` or `--pipeline`) and exits 0; when a command completes normally (not after Ctrl-C or a crash), the next queued one replaces the process (`os.execv`), keeping the lock, and its outcome goes to `_bmad-output/sdlc/queue-history.jsonl`. Exit codes: 0 passed or queued; 1 internal error, failed preflight or refused issue; 2 escalated, blocked or `awaiting_owner`.
  - Robust git (AD-27): `git fetch` retries ref-lock errors with backoff, and a fetch that still fails only fails the script step that needed it; `sdlc resume` removes `*.lock` files no process holds from each run worktree's git dir; learn branches rebase onto `origin/main` before their PR.

## Known pitfalls

- The guard reads every Bash command as text, heredoc bodies included. Inline code (`python3 -c`, `node -e`) that mentions a retailer domain, or a heredoc whose text contains a blocked command such as `terraform apply`, is denied even though nothing would run. Write the content with the Write tool, or put code in a script file and run that.
- When the owner approves a retailer in `docs/source-register.md`, the backend tests and startup fail until `config/retailers.yaml` has an entry for it and `config/known-eans.yaml` has at least two distinct valid EANs for it. Approval takes effect only after a rebuild and deploy, because the register is bundled into the jar.
- `ro.pricechecker.lookup.AdapterCatalog` refuses to start unless the `RetailerAdapter` bean ids and the `config/retailers.yaml` ids match one-to-one (AD-7). Main code has `retailer.celro.CelroAdapter` (story 2.10) and `retailer.evomagro.EvomagAdapter` (story 2.11), one for each `retailers.yaml` id; a new `retailers.yaml` entry needs its adapter bean in the same PR. The test-only `lookup/StubAdapters` (found by component scan) registers a no-op adapter for each id that no real adapter under `ro.pricechecker.retailer` serves, so Spring tests still start while a new entry's adapter is missing. It finds real adapters by classpath scan and creates each with its public no-arg constructor, so an adapter takes no constructor dependencies (`RetailerHttp` is a parameter, AD-7). `retailer/celro/CelroAdapterContextTest` names the adapter id and class each context holds; update it when an adapter lands.
- Adapter tests read pages only from `fixtures/<retailer>/` through a fake `RetailerHttp` (T-2, T-3). The cel.ro fixtures and selectors (`#product-price`, `.stoc_produs`, `.product-ean`) are synthetic and marked `[ASSUMPTION]` until story 2.12 records real pages; the evomag.ro fixtures are synthetic until story 2.13. Each `fixtures/<retailer>/README.md` lists what each page covers. The two adapters combine C-6 steps differently, and both return `Unavailable(UNPARSEABLE)` only when no step gives any fact:

  | Adapter | Step order | How steps combine |
  |---|---|---|
  | `CelroAdapter` (2.10) | JSON-LD, meta tags, own selectors | Field by field: each field comes from the first step that has it |
  | `EvomagAdapter` (2.11) | JSON-LD, schema.org microdata, meta tags | Whole step: the first step with a price wins; otherwise the first step with any fact, with a `null` price |

  `retailer.evomagro.EvomagPage` keeps its own microdata reader and a copy of the package-private `extract.SchemaAvailability`. Moving both into `extract` is deferred (story 2.11). Its microdata step reads the first Product scope, including nested scopes, until story 2.13 checks it against real pages.
- `LookupService` catches any `Exception` from an adapter per row and returns `UNAVAILABLE`, so a Lookup stays 200 (AD-5). `LookupService` still gets an empty `Optional<RetailerHttp>`: story 2.8 did not wire in `fetch.FetchClient` (`bind(retailerId)`), and no story in `epics.md` names that step yet. So every enabled retailer with a known EAN is `UNAVAILABLE`. `retailerName` is the register domain until `retailers.yaml` gets a `name` field. Jackson `default-property-inclusion: non_null` in `application.yaml` keeps non-FOUND rows to their four fields; do not remove it.
- Lookup execution and cache (AD-10, AD-11, ADR 0011, story 2.8). The steps for each Approved retailer, in order:

  | Step | Row |
  |---|---|
  | Adapter disabled or `fetching: stopped` | `DISABLED` |
  | `BlockStore.isBlocked` | `UNAVAILABLE`, no adapter call |
  | EAN not in `known-eans.yaml` | `NOT_FOUND`, no adapter call |
  | Cache hit | Cached verdict, with its original `fetchedAt` |
  | Load | Adapter call on its own virtual thread, then normalization |

  - Normalization: an `eanOnPage` that differs from the request, ignoring leading zeros, gives `NOT_FOUND`. A missing `eanOnPage` stays `FOUND`. A price is kept only when the currency is exactly `RON`.
  - Deadline: the Lookup waits for each row until `deadlineMs`, counted from the Lookup's start (default 4000 ms). A waiter that gives up leaves the shared load running, and the load's result still fills the cache.
  - `cache.ResultCache<K,V>` is generic. It wraps a Caffeine `AsyncCache` with a virtual-thread executor, and `cache` uses no project package (AD-1). Concurrent misses for one `(retailerId, ean)` share one load. A loader result of `null` (for `UNAVAILABLE`) or an exception leaves no entry. TTL is checked against the instant the loader returned, on the injected `Clock`.
  - The TTL comes from `price-checker.cache-ttl` (env `PRICE_CHECKER_CACHE_TTL`, default `15m`; `30s` and `PT15M` forms also work), wired by the root `LookupCacheConfig`. A blank, unparseable or non-positive value stops the app.
  - Logging: each row writes one `INFO` line `event=lookup_row` with `ean`, `retailer`, the status in `outcome` and `durationMs`. `durationMs` is measured from the Lookup's start, not per row.
  - Tests that build `LookupService` pass a `registry.BlockStore` and a `ResultCache`, and never sleep (T-5).
  - Story 2.8 deferrals: a hung adapter load has no time limit, and its key stays pending, so every Lookup of it is `UNAVAILABLE` until the adapter returns. The cache has no size bound and its executor is never closed.
- `GET /api/status` is `api.StatusController` (story 2.9, AD-3, AD-16). Like a Lookup, it calls `RuntimeSwitch.refresh()` and logs a rejected `runtime.yaml` through `LookupLog`. So a local run without `runtime.yaml` shows every retailer `enabled: false`. It lists only Approved retailers, in `retailers.yaml` order. Each entry has `retailerId` and `retailerName` (both the register domain), `enabled` (adapter enabled and `fetching: allowed`), `blocked` (`BlockStore.isBlocked`) and `notBefore` (`BlockStore.notBefore`, UTC). `notBefore` appears only while it is in the future. The Approved filter and the `enabled` rule are copied from `LookupService`; change both together (story 2.9 deferral).
- The Kill switch fails closed (AD-9, story 2.3): `registry.RuntimeSwitch` reads `runtime.yaml` from property `price-checker.runtime-file` (env `PRICE_CHECKER_RUNTIME_FILE`, default `/opt/price-checker/config/runtime.yaml`, wired by `ro.pricechecker.RuntimeSwitchConfig` because `registry` reads no property, AC 1.5.4). No such file exists outside the VM until stories 3.2 and 3.4, so a local run shows every row `DISABLED` and logs `event=runtime_config_rejected`, `outcome=MISSING` on the first Lookup after each 15 s. Point the env var at a file with `retailers: { <domain>: { fetching: allowed } }` to fetch locally. There is no scheduler: `LookupService` calls `refresh()` once per Lookup and the file is re-read only when 15 s passed on the injected `Clock`. A stopped retailer is `DISABLED` before the known-EAN check and any adapter call. Every retailer entry needs `fetching: allowed|stopped`; an entry without it rejects the whole file and the last good settings stay. An entry may also hold `clearGeneration` (a non-negative integer, default 0; any other value rejects the file) and `runnerBlock` (present means blocked), both read by `BlockStore` (story 2.6), and `notBefore` (an ISO-8601 instant, quoted or unquoted; a runner 429, story 2.7; any other value rejects the file).
- Every retailer request goes through `ro.pricechecker.fetch.FetchClient` (AD-6, C-12, story 2.4): `bind(retailerId)` returns a `RetailerHttp` for one `retailers.yaml` id (an unknown id throws). It sends nothing (`Unavailable(REFUSED)`) unless the retailer is Approved, its adapter is enabled, `fetching: allowed` is set, the URL is `https` on the register domain or `www.` of it (port 443, no userinfo), and a rate and concurrency permit is free before `deadlineMs`; redirect hops and retries are checked again. Before each page attempt it also asks `fetch.RobotsCache` whether robots.txt allows the path for the product token `price-checker` (story 2.5): a disallowed path, or an unparseable robots.txt, gives `Unavailable(BLOCKED)` with nothing sent; an unreachable one (5xx, 429, timeout, bad redirect, no permit) gives `REFUSED` and is not kept. robots.txt is loaded on a host's first request (no prefetch), takes a rate slot inside that request's deadline, is never retried and is kept 24 h on the injected `Clock`. A test that builds `FetchClient` (both constructors take a `registry.BlockStore`; give it a file under `@TempDir`) with the package-private constructor must pass a `RobotsCache` seeded allow-all for each host it uses (`RobotsTest.allowAll(clock)` seeds `a.example` and `www.a.example`), or every request count and rate slot gains the robots request. Only timeouts and 5xx are retried (at most 2, 250 ms then 500 ms, through the injected `Sleeper`); 404 and 410 give `NotFound`. A 429 is a pause, never a Block (story 2.7): `fetch.RetryAfter` turns `Retry-After` (delta-seconds or IMF-fixdate; missing or unparseable means 60 s; capped at 10 years) into `notBefore`, and `BlockStore.recordRetryAfter` persists it in `blocks.json` and never moves it earlier. When the effective `notBefore` is before the deadline the client sleeps until it and retries once (separate from the 5xx retries); otherwise `Unavailable(REFUSED)`. A robots.txt 429 records `notBefore` too and is not retried. While `BlockStore.notBefore` (the later of `blocks.json` and the `runtime.yaml` `notBefore`) is in the future, every request for that retailer, robots.txt included, gets `Unavailable(REFUSED)` with nothing sent, and `isBlocked` stays false. No operator action clears a `notBefore` short of editing `blocks.json`. Failures reach the adapter as `FetchFailure` (an `IOException`), so an adapter writes `catch (FetchFailure f) { return f.outcome(); }`. The user agent `price-checker/<version> (+<contactUrl>)` is built at startup by the root `FetchClientConfig` from `price-checker.contact-url` (env `PRICE_CHECKER_CONTACT_URL`, default the repo URL); the app refuses to start when it is blank or not an absolute http(s) URL, or the string contains `bot`, `robot`, `crawl` or `spider` in any case. Without a jar `Implementation-Version` the version reads `dev`. `JdkTransport` buffers the whole body with no size cap, and the concurrency-permit wait and the robots.txt single-flight wait use wall time, not the injected `Clock` (story 2.4 and 2.5 deferrals).
- A Block stops a retailer until an operator clears it (AD-9, FR-11, story 2.6). A page 403, a challenge marker (`fetch.ChallengePage`: `_cf_chl_opt`, `cf-browser-verification`, `_Incapsula_Resource`, `px-captcha`) in a 2xx or 5xx body, or a robots.txt disallow of one path calls `registry.BlockStore.record`, is not retried, and makes `FetchClient` refuse every later request for that retailer, robots.txt included, with `Unavailable(BLOCKED)`. `BlockStore` is the only reader and writer of `blocks.json` (property `price-checker.blocks-file`, env `PRICE_CHECKER_BLOCKS_FILE`, default `/opt/price-checker/state/blocks.json`, wired by `ro.pricechecker.BlockStoreConfig`). A missing file means no Blocks; a file that does not parse, or has an unknown `reason` or a bad known field, stops the app at start (fail closed). Unknown fields are ignored (since story 2.7). An entry holds the Block fields (`blockGeneration`, `blockedAt`, `reason`) all or none, an optional `notBefore`, and at least one of the two; every write keeps both. A story 2.6 jar refuses to start on a `blocks.json` that holds a `notBefore`, so a rollback past story 2.7 needs that field removed first. A Block is active while its `blockGeneration >= clearGeneration` of the polled `runtime.yaml` (default 0), or while that retailer has a `runnerBlock` key; only a `clearGeneration` increment ends a generation Block. Each new Block logs one `WARN` line `event=retailer_blocked` with the reason in `outcome`. A failed `blocks.json` write keeps the Block in memory only and is not logged (story 2.6 deferral). `arch/NoRetryWorkaroundTest` fails the build on a proxy, a second user-agent value or code that changes request headers in main sources (AC 2.6.4).
- CI `secret-scan` checks every commit in the PR, so a secret-like string (for example an AWS-style key in a test fixture) fails it even if a later commit removes it. There is no allowlist; build such strings at runtime from parts, as the canary in `.github/workflows/ci.yml` does.
- Backend main code must not contain retailer domain or selector-like string literals (for example a literal ending in `.yaml`); `backend/src/test/java/ro/pricechecker/arch/RetailerTextScan.java` fails the build. Tests use `*.example` domains. Schema.org values count too: match an availability URL by its text after the last `/`, never as a literal (story 2.1).
- `npm install` on macOS can drop the optional `node_modules/@emnapi/core` and `@emnapi/runtime` entries from `web/package-lock.json`. Local `npm ci` still passes, but CI `web` fails at `npm ci` with `EUSAGE` (story 1.3). After a dependency change, check that both entries are still in the lockfile, or restore them from `origin/main`.
- Spring Boot 4 moved `@WebMvcTest` to the test dependency `spring-boot-starter-webmvc-test` (BOM-managed, already in `backend/build.gradle.kts`); the old `spring-boot-starter-test` import alone does not find it (story 1.4).
- Application events go only through `ro.pricechecker.lookup.LookupLog` (ADR 0017): its fields come from a private enum, so a new field needs an ADR 0017 change first. Never log the raw EAN input, an exception message, an IP or a user agent; a rejection puts the `EAN_*` code in `outcome`. Spring's own text logs still share stdout with these JSON lines (story 1.4 deferral), so do not parse stdout as pure JSON lines.
- Save a fetched page (fixture or Health check report) only after `ro.pricechecker.fetch.PageStripper.strip(String)` (S-7, T-2, AD-16, story 2.2). It keeps only JSON-LD whose `@type` is or contains `Product` (also `…/Product`, `…:Product`, inside `@graph`), re-serializes it with every `<` as `<` (so `19.90` may become `19.9`), drops JSON-LD that does not parse, and cuts every text node over 200 characters, not only descriptions. Video, audio, `on*`/`style`/`data-*` attributes and non-fact JSON-LD fields such as `review` still survive (story 2.2 deferrals). In main code write a MIME type with `+` split (`"application/ld" + '+' + "json"`), or `RetailerTextScan` reads the `+` as a CSS combinator.
